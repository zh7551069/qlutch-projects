## 1. 范围与不做

本契约只覆盖 A4 已受理导入作业之后、由 `services/worker` 执行的异步路径：

- 把 `accepted` 迁到 `running` / `map_ready` / `failed_retryable` / `failed_terminal`
- 生产路径经 `services/airuntime` 真正跑 S01（教材解析与知识点挖掘），成功则把可用地图写入知识包
- 该学习者首次作业进入 `map_ready` 时，按 A4 已锁规则把 `has_first_pack` 置为 `true`
- 地图已成并可见之后，再触发 S02 对当前及即将解锁节点的小批量预出题；S02 成败不影响 `map_ready`，也不进入等待页闸门
- 为 S01 写入用量账本（失败也记账）；若跑了 S02，按 S02 子类另记，不与 S01 或 S05 混账
- 与 A4 作业查询字段保持兼容；查询仍只读

不在本契约：

- 新增学习者 HTTP 路径或方法；不加后管 / 内部路径（`/internal/v1/**`）
- 为抖音 / B 站、ISBN / 书名开 endpoint（沿用 A4 与方案 H8）
- 改 A4 已锁的受理路径、字段、错误码拼写，或改 `status` 枚举已有值的含义
- 新增 `next_step` 值，或改 A1 已锁身份路径与 schema
- 规定 prompt、模板正文、worker 内部协议（队列消费格式、回调 body、模型请求体）或供应商 / 温度 / 费率
- 默认首页内容、等待页动画与文案样式、端 UI 接线
- 把 A4-O2 的进程默认值（预签名秒数、材料字节上限、轮询间隔、幂等键保留时长）写成已锁产品口径
- 部署、生产密钥

配置变量名对齐已有示例，只锁定名称、不锁定取值：`QLUTCH_S3_*`、`QLUTCH_WORKER_QUEUE`、`QLUTCH_WORKER_HEARTBEAT`。示例里的心跳时长等数字不是本约已锁口径。不在本文写密钥或厂商取值。

## 2. 状态机与迁移

作业 `status` 枚举与含义沿用 A4 §4.3，本约不得改已有值的语义。

| 值 | 对应 phase B / D03 用语 | 谁写入 | `map_ready` | `retryable` |
|---|---|---|---|---|
| `accepted` | 受理 | A4 受理时 | `false` | `false` |
| `running` | 解析中（地图生成中） | A5 | `false` | `false` |
| `map_ready` | 地图已成，可进 | A5 | `true` | `false` |
| `failed_retryable` | 失败可重试 | A5 | `false` | `true` |
| `failed_terminal` | 失败且不可重试 | A5 | `false` | `false` |

不变量（沿用 A4，本约必须维持）：`map_ready == (status == map_ready)`；`retryable == (status == failed_retryable)`。等待页只有在 `map_ready == true`（即 `status=map_ready`）时才允许进入默认首页入口；`accepted` 与 `running` 都不可提前进入。S02 不得堵塞本状态，也不得为此另设查询字段或状态值。

本约允许的迁移：

1. `accepted` → `running`：worker 取出该作业并开始（或即将开始）跑 S01。
2. `running` → `map_ready`：S01 已写出可进入的知识地图；**必须先写好地图，再把 `status` 置为 `map_ready`**，查询不得在地图尚未落库时看到 `map_ready`。
3. `running` → `failed_retryable` 或 `failed_terminal`：S01 未产生可用地图。区分规则见第 6 节。
4. `accepted` → `failed_retryable` 或 `failed_terminal`：作业尚未进入运行，但已确定无法开始或无法用当前材料开始 S01（例如对象已不可读）。不得借这条路径跳到 `map_ready`。

禁止：

- 生产路径把 `accepted` 或 `running` 直接写成 `map_ready`，却没有经 airuntime 真正跑 S01（或命中第 4 节允许的「同一材料、同一模板版本的成功地图复用」）
- `map_ready` 在本切片再迁到其他状态。S02 失败、后续预出题或查询都不得回滚地图已成
- 查询接口或跳过接口改写作业 `status`
- 同一作业在用户可见的失败态与 `running` 之间来回翻转（worker 内部自动重试期间应保持 `running`，放弃本作业后再迁到失败态）

空包创建与导入 `202` 受理仍只把作业停在 `accepted` 并入队，不得因受理本身把 `status` 写成 `map_ready`，也不得因此把 `has_first_pack` 置真。

## 3. 生产 / 测试路径约束

生产路径：

- 必须经 `services/airuntime` 的统一入口跑 S01。知识域不得直接调用模型供应商 SDK（I04）。
- 禁止用 mock、夹具或内部捷径把生产作业直接标成 `map_ready`。
- 提供方未配置、无生效模板、入口拒绝或 S01 失败时：按第 6 节迁到失败态并记账，不得假装已生成地图。

测试路径：

- 测试可以保留夹具（例如既有的 `TestingSetJobStatus`）以便合同测试推进作业状态。
- 夹具不得注册为 HTTP 路由，不得出现在学习者或后管的对外路径上。
- 夹具不得走进生产路径：只允许出现在测试构建或测试专用装配中，不能靠生产环境开关把 S01 换成「直接 map_ready」。

本约不规定夹具的函数签名或内部协议。

## 4. S01 与 S02 时序与闸门

时序（与 phase B §7、I05 §2.2 对齐，本约把它写成 C 级确定性结论）：

1. A4 受理导入：作业为 `accepted`，入队，返回 `202`。API 不在该请求内跑完 S01。
2. worker 将作业迁到 `running`，调用 airuntime 做 S01。上下文按页、按段或按入口分片送入；一次请求不得塞入完整教材，也不得把完整教材送进模板（D04 / I04）。
3. S01 成功：把目录 → 章节 → 考点的地图写入该知识包，然后将作业迁到 `map_ready`。若这是该学习者首次 `map_ready`，按第 5 节置 `has_first_pack=true`。`has_first_pack` 的更新须与 `map_ready` 同时或紧随其后对查询与身份刷新可见。
4. **仅在 `map_ready` 已提交之后**，再触发 S02：对当前及即将解锁的节点做小批量预出题，不得在用户打开地图的同步请求里跑完，也不得把整张地图一次出满。预生成批量以「能开出一卷并减少练习中补题」为目标；D04 所写的 100 是可配上限，不是本约已锁数字，不得在导入时按上限出满。
5. S02 的成功、失败、部分成功或尚未开始，都不得改变该导入作业的 `status` / `map_ready` / `retryable`，也不得改变 `has_first_pack`。等待页闸门只看 `map_ready`，客户端不得为等 S02 而挡住默认首页入口。
6. `GET /v1/knowledge/jobs/{id}` 不变状态、不触发 S01、不触发 S02。

同一已传材料、同一模板版本上的成功地图结果允许复用，避免用户按第 6 节重试时整本重跑；材料变更或模板升级后走新生成（D04）。复用仍须经 airuntime 入口判定并记账，不得在生产路径用夹具或领域旁路直接标 `map_ready`。本约不定模板正文、缓存键落地细节或复用 TTL。

本切片没有抖音 / B 站 / ISBN / 书名入口。S01-META 若实际未走模型（例如纯书目），记非模型调用、不得虚报 token；本刀不为这些入口补路径。

## 5. `has_first_pack` / `next_step` 衔接

完全沿用 A4 §3，本约不另起一套，也不改 A1 定稿：

- `account.has_first_pack` 仍是 A1 `AccountSummary` 中的那个布尔字段，身份域只读，用于计算 `next_step`。`next_step` 仍只是 `NEED_ONBOARDING` / `NEED_FIRST_PACK` / `READY_HOME`。
- `has_first_pack` 表示首包步骤已完成。写入点仍是两处，满足任一即置为 `true`：该学习者首次有导入作业进入 `map_ready`，或 `POST /v1/knowledge/first-pack/skip` 成功。一经为真，本切片不定义撤销。
- 创建空知识包与导入 `202` 受理仍不得置真。
- 首次 `map_ready` 或跳过成功之后，本约相关查询以及随后的身份刷新都应看到 `has_first_pack=true`。若建档已完成，`next_step` 为 `READY_HOME`，会话刷新不得把用户打回 P04；若建档未完成，`next_step` 保持 `NEED_ONBOARDING`。
- 已经 `has_first_pack=true` 后再跳过：仍为成功 2xx，不把已完成打回未完成，不清除已有知识包或作业。
- 不得新增 `next_step` 值，不得让端上本地标志成为权威。

H3（老用户验码后是否跳过建档与首包）仍是实施假设，不是已锁产品口径；否定时只改身份域判定，不改枚举，也不改上述写入点。

## 6. 重试规则

面向用户的重试对齐 A4 §5.3，不另设「重试」子资源：

- 对 `failed_retryable` 的作业，客户端使用**新的** `Idempotency-Key`，带上同一 `pack_id` 与同一 `material_id` 再次调用 `POST /v1/knowledge/imports`，创建一条新作业。
- 服务端必须复用已传材料的对象键，不得要求用户把同一文件再传一遍，除非材料损坏或校验失败需要换文件（I05）。
- 原失败作业保持其失败态，不在原 `job_id` 上把状态改回 `accepted` 或 `running`。
- 同一密钥重放同一请求体的规则仍按 A4：不创建新作业，响应与当时的 `GET` 一致。
- 同一知识包已有 `accepted` 或 `running` 的导入作业时，新的提交仍是 `CONFLICT`（409）。已失败或已 `map_ready` 的作业不占据这条互斥。

worker 侧何时迁到哪一种失败态：

- **`failed_retryable`**：S01 未产生可用地图，但同一份材料稍后仍可能成功。典型情况包括提供方瞬时错误、超时、未配置提供方、入口暂时拒绝、运行时熔断或紧急停用后的中止。此时 `retryable=true`。已形成的地图若尚未达到可进入标准，不得标 `map_ready`；若在安全点停下时地图已经可进入，则应标 `map_ready` 而不是失败（I05：已形成的地图保留）。
- **`failed_terminal`**：同一份材料无法再合理成功。本轮锁住的一条：材料对象不可恢复地缺失或损坏，继续用同一 `material_id` 提交不会得到不同结果。此时 `retryable=false`；客户端不应再拿同一 `material_id` 重试，需要的话应重新申请预签名并上传。其余终态原因不在本轮编造，见第 10 节 A5-O3 / A4-O3。
- 在材料对象仍完整可读、且尚未出现已补丁的终态原因时，优先迁到 `failed_retryable`，不要把未锁定的原因写成 `failed_terminal`。

worker 在将本作业标为失败之前，是否自动重试、次数上限、回退间隔与作业超时：本轮不锁死，见 A5-O1。未锁死前不得把某个次数或秒数写进实现当产品口径。若实现做内部自动重试，须在放弃前保持 `status=running`，每一次内部尝试在账本上写重试序号（I04）。用户侧「再试一次」永远是新作业、新的尝试，须能与上次失败对上。

## 7. S01 账本

对齐 D03 §4.7、D04、I04，本约只把导入作业路径上必须遵守的规则写成确定性结论：

- 能抽库不新生成、能缓存不重复生成；缓存或复用命中必须能在账本里看出来。S01 不得把题库抽题记进本场景。
- 只送必要片段；禁止完整教材进入模板或一次请求。输入指纹可以入账，指纹不是原文。
- 识别 / 转写与文本生成分账：场景码为 S01；子类至少能拆出实际发生的 S01-OCR、S01-ASR、S01-META。拍照等图片源若做了识别，须能看到 OCR；音频若做了转写，须能看到 ASR；纯文本粘贴笔记不得虚报 OCR / ASR。无模型的调用记非模型或 token 为 0，不得虚报。
- 按档位（轻 / 识别 / 标准 / 重）路由与计量，不按供应商写死；本文不指定供应商、型号、温度或费率。未配置费率不得编造单价。
- 失败也要记账，且默认不误扣用户侧练习 / 提示 / 解答 / 讲题次数。S01 本身不消耗这些次数。若实现先占了额度，失败必须回滚或补发，不得改成「失败也默认扣死」。账本失败行保留；纠错只追加，不覆盖已成功记账的原始行。
- S02 预出题（子类「后台预生成」）与 S01 分账；S05 讲题中出题不得写入 S02，也不得与 S01 混账。
- 每条流水至少包含：场景码、子类、是否缓存或复用命中、成功或失败、重试序号、token 或对等计量（页、时长等）、关联知识包或导入作业、模板版本（若有）、调用方、时间。调用方在本路径为终端用户业务，不是后管预览。
- 默认不存教材原文、完整提示词或完整模型输出。常规日志与错误 `details` / `failure_message` 遵守同一条脱敏。用量流水须能按场景码、子类、复用命中查询与汇总（A33 / A34 出口能力）；本刀不加后管路径。
- 缺场景码或子类的事件视为记账缺陷，不得记入「其他」，也不得当成功消耗。

本切片验收强调：生产路径上一次 S01 尝试（成功或失败）之后，必须能查到对应的 S01 流水。S02 若已触发，另有 S02 流水；S02 没有流水或失败，不得作为拒绝 `map_ready` 的理由。

## 9. 错误码

本轮不新增学习者 HTTP 错误码，也不把作业失败表现成查询接口的 5xx：作业存在且属于当前学习者时，`GET` 仍为 `200`，失败只体现在 `status`、`retryable` 与可选的 `failure_code` / `failure_message`。

A4 §7 的受理与查询错误码继续有效（含 `AUTH_*`、`VALIDATION_*`、`NOT_FOUND`、`CONFLICT`、`IDEMPOTENCY_KEY_MISMATCH`、`RATE_LIMITED`、`INTERNAL`）。`INTERNAL` 不得用来吞掉校验、冲突、限流，也不得把已存在作业的 S01 失败伪装成查询失败。

airuntime / I03 的 `AI_*`（未配置提供方、模型调用失败、场景被紧急停用等）只作为内部失败来源，须翻译成本作业的失败态与可选 `failure_code`，不得把提供方原文、密钥或教材正文回给客户端。本轮不预先锁一份尚未出现的 `failure_code` 清单；若实现写出稳定机器码，须是真实发生过的原因，并以契约补丁追加（A4-O3）。

## 11. 实现与验收

- 本轮不改机器源；合同测试仍以已确认 A4 生成物为准。实现本约不要求、也不允许为 A5 改 A1 / A4 已锁 OpenAPI 定义。
- 生产路径必须真正调用 airuntime 跑 S01；禁止 mock 直接 `map_ready`。测试夹具不得是 HTTP 路由，不得走进生产路径。
- 查询到 `map_ready` 时，该知识包已有可进入的地图；首次 `map_ready` 后 `has_first_pack=true`，`next_step` 规则与 A4 一致。
- 失败可重试作业可用新的 `Idempotency-Key` 与同一材料再次提交导入，并复用对象键。
- 生产路径上的 S01 尝试（成功或失败）须有可按场景码 / 子类查询的 S01 账本流水。S02 不堵塞闸门。
- `GET` 作业查询不变状态、不触发 S01 / S02。
- 本契约不部署，也不把中间过程的单独产品验收写成实施闸门。
- 三端共用 A4 已锁路径与字段，不允许各端为 S02 或 worker 私加查询协议。
