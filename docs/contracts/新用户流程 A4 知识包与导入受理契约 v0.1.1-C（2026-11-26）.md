## 1. 范围

本契约只覆盖学习者知识域中，本刀（附录 A4）需要的同步受理、作业查询与首包跳过：

- 创建空知识包
- 为拍照、文件、粘贴笔记申请 S3 兼容预签名上传
- 提交导入（`Idempotency-Key`，HTTP 202 + `job_id`）
- 查询导入作业（状态、进度文案、失败原因、`pack_id`、地图是否可进）
- 跳过首包（「我没有材料」，`POST /v1/knowledge/first-pack/skip`）
- 与身份域 `has_first_pack` / `NEED_FIRST_PACK` 的衔接规则

不在本契约：

- A5 worker 的 S01 地图生成实现、S02 预出题实现，以及出题 / 知识点挖掘的请求体、worker 内部接口、队列消费协议
- 抖音 / B 站入口（端上 toast「功能尚未开放」即可，**不**为本约增加 endpoint；客户端不得发这些请求）
- ISBN / 书名入口（方案 §9 **H8**：本切片跟 Figma，五种入口的其余两项留待后续切片）
- 默认首页内容、等待页动画与文案样式、系统权限调起
- 后管 / 内部知识域（`/internal/v1/**`）；本刀不私自加后管端点
- 在接口体或错误 `details` 中存放、回显教材原文

三端共用这一套路径、字段与错误码，不允许各端私改。知识域路径挂在 `/v1/knowledge/...`，健康检查仍是 `/healthz`、`/readyz`，不鉴权、不返回业务数据。

## 2. 平台约定（沿用 I03 与 A1，不另起一套）

- 学习者路径：`/v1/knowledge/...`。名词资源，动作用 HTTP 方法或明确子资源。
- 访问令牌：`Authorization: Bearer`；只允许访问 `/v1/**`。内部令牌打到本前缀一律 `AUTH_WRONG_REALM`。本约接口均需登录。
- 每个响应带 `X-Request-Id`；请求可带同名头，服务端也可补发。
- 成功：直接返回资源 JSON，用 HTTP 状态表达结果（创建知识包 `201`，申请预签名 `200`，受理导入 `202`，查询作业 `200`，跳过首包 `200`）。失败统一信封，字段与 A1 相同：

```json
{
  "error": {
    "code": "AUTH_EXPIRED",
    "message": "给人看的说明，可随端做本地化",
    "details": {}
  },
  "request_id": "…"
}
```

客户端只依赖 `code`（以及作业成功体里的 `status`），不解析 `message` 或 `progress_message`。`details` 可选，不得放入教材原文、完整提示词、完整模型输出、密钥、对象存储密钥或材料正文摘录。

- 提交导入与跳过首包必须带 `Idempotency-Key`。同一身份、同一密钥、同一请求体返回与首次相同的结果，不重复执行（导入不得创建第二条作业；跳过不得把已完成打回未完成，也不得清除已有知识包或作业）。同一密钥不同请求体返回 `IDEMPOTENCY_KEY_MISMATCH`，不执行。只读查询不要求幂等键。创建知识包与申请预签名本约不要求幂等键。
- 对象存储走 **S3 兼容预签名**。云厂商以配置注入，不进领域层，不写进路径或 schema。实现读取下列变量名（与《云服务配置 · 新用户流程（待填 · 2026-11-25）.env.example》对齐），**本文不写值**，密钥待辉后补，不进仓库、不进 Cloud 任务正文：`QLUTCH_S3_ENDPOINT`、`QLUTCH_S3_REGION`、`QLUTCH_S3_BUCKET`、`QLUTCH_S3_ACCESS_KEY`、`QLUTCH_S3_SECRET_KEY`。作业入队若使用已有工人配置，只引用名称 `QLUTCH_WORKER_QUEUE`、`QLUTCH_WORKER_HEARTBEAT`，同样不写值。
- 材料文件在对象存储；关系型只存知识包、材料元数据（含对象键）、导入任务。接口不接收、不返回材料正文；预签名 PUT 的字节不经过本 API 转发。客户端不直连改桶策略，也不得自拟对象键。
- 短信 / 模型 / 对象存储的具体供应商本约不锁定。

## 3. 与身份域衔接

身份域契约（A1 v0.1.0-C）已锁定：

- `account.has_first_pack` 仍是 A1 `AccountSummary` 中的那个布尔字段，身份域只读，用于计算 `next_step`。本约不改 A1 定稿文件，也不新增字段或 `next_step` 枚举值（仍为 `NEED_ONBOARDING` / `NEED_FIRST_PACK` / `READY_HOME`）。
- 在本约知识域写入规则里，`has_first_pack` 的含义是：**首包步骤已完成**（该学习者首次有导入作业进入 `map_ready`，或用户经 `POST /v1/knowledge/first-pack/skip` 选择「我没有材料」）。
- 验码、刷新会话、读写建档的成功响应都带当前 `next_step` 与 `account`。三端必须按服务端给出的 `next_step` 路由，不得自行根据本地标志猜测。

本约补充知识域的写入规则（确定性结论；写入规则引本轮 Owner 锁定说明 / 点名要求，产品行为引已确认 phase B §7.4）：

1. **创建空知识包**（`POST /v1/knowledge/packs`）或 **受理导入**（`202`）都**不得**把 `has_first_pack` 置为 `true`。否则刷新会话会得到 `READY_HOME`，等待页「地图生成完成才能进首页」的闸门会被绕过。
2. **`has_first_pack` 的写入点**有两处，满足任一即置为 `true`：该学习者首次有导入作业进入 `map_ready`（地图已成、可进）；或跳过首包接口成功。一经为真，本切片不定义撤销。
3. 本约各成功响应都带当前 `account` 与 `next_step`（复用 A1 schema），避免三端在等待页、跳过与身份态之间分叉。A5 把作业迁到 `map_ready` 之后，或跳过接口成功之后，本约接口与随后的身份刷新都应看到 `has_first_pack=true`。若建档已完成，`next_step` 为 `READY_HOME`，会话刷新不得把用户打回 P04；若建档未完成，跳过仍记录为首包步骤已完成，但 `next_step` 保持 `NEED_ONBOARDING`。
4. 本约不把「建档未完成」当作知识域的硬拒绝条件；路由仍以身份域 `next_step` 为准，避免知识域再做一套建档闸门。
5. 「我没有材料」走 `POST /v1/knowledge/first-pack/skip`：不创建导入作业、不进等待页、不要求先有知识包，直接按第 3 条计算 `next_step` 并走默认首页入口（首页内容本切片不实现）。不得用客户端本地跳过冒充已写入，也不得为此新增 `next_step` 值。

实施假设（方案 §9 **H3**，不是已确认产品口径）：老用户验证码通过后，若建档与首包步骤均已完成，则 `READY_HOME`；仅未完成建档者进 7 步；建档完成但首包步骤未完成者 `NEED_FIRST_PACK`。H3 若被否定，只改身份域服务端判定，不改枚举名，也不改本约的 `has_first_pack` 写入点。

## 4. 标识与枚举

### 4.1 导入源 `source`

| 值 | 对应入口 | 说明 |
|---|---|---|
| `camera` | P04 主帧拍照 / 投放拍摄 | 仅图片类媒体 |
| `file` | 更多导入 · 上传文件 | PDF / PPT / Word / 图片 / 音频 |
| `paste_note` | 更多导入 · 粘贴笔记 | 笔记正文先作为材料上传到对象存储，再提交导入，**同样进入 S01**，不得在受理时把作业标成已完成或跳过解析 |

其它值：`VALIDATION_INVALID_SOURCE`。

粘贴笔记没有单独的「同步完成」接口，也不在请求体里携带笔记全文。端上先调预签名，再按 `text/plain` PUT 正文，再提交导入。等待页闸门与拍照、文件相同。

### 4.2 允许的 `content_type`

须与 `source` 匹配，否则 `VALIDATION_UNSUPPORTED_MEDIA`。下表是本切片三端共用的允许值；同一格式的罕见别名若要追加，用契约补丁，不得由某端私放视频、ISBN 或书名类。

| `source` | 允许的 `content_type` |
|---|---|
| `camera` | `image/jpeg`、`image/png`、`image/webp`、`image/heic`、`image/heif` |
| `file` | `application/pdf`；`application/vnd.ms-powerpoint`、`application/vnd.openxmlformats-officedocument.presentationml.presentation`；`application/msword`、`application/vnd.openxmlformats-officedocument.wordprocessingml.document`；以及 `camera` 行的图片类型；`audio/mpeg`、`audio/mp4`、`audio/x-m4a`、`audio/aac`、`audio/wav`、`audio/x-wav`、`audio/wave` |
| `paste_note` | `text/plain` |

字节上限本约不锁死。超出服务端上限时 `VALIDATION_MEDIA_TOO_LARGE`（400），可在 `details.max_bytes` 给出上限，但不得把某个具体数字写成产品已终锁。

### 4.3 作业状态 `status`

| 值 | 对应 phase B / D03 用语 | 谁写入 | `map_ready` | `retryable` |
|---|---|---|---|---|
| `accepted` | 受理 | A4 受理时 | `false` | `false` |
| `running` | 解析中（地图生成中） | A5 | `false` | `false` |
| `map_ready` | 地图已成，可进 | A5 | `true` | `false` |
| `failed_retryable` | 失败可重试 | A5 | `false` | `true` |
| `failed_terminal` | 失败且不可重试（为 I05 / A5 预留） | A5 | `false` | `false` |

不变量：`map_ready == (status == map_ready)`；`retryable == (status == failed_retryable)`。等待页只有在 `map_ready == true`（即 `status=map_ready`）时才允许进入默认首页入口；`running` 或 `accepted` 都不可提前进入。S02 预出题不得堵塞本状态，本约也不为 S02 另设查询字段或状态值。

A4 只保证受理后作业为 `accepted`、可查询、材料对象键保留在服务端。`running` / `map_ready` / 失败态由 A5 迁移；A5 未接上时，查询可以一直停留在 `accepted`，此时不得因该作业把 `has_first_pack` 置真，也不得把 `status` 写成 `map_ready`。

## 5. 接口

未特别声明的接口均产生 JSON。无访问令牌为 `AUTH_REQUIRED`（401），令牌过期或已吊销为 `AUTH_EXPIRED`（401）。资源不存在、或存在但不属于当前学习者（不可枚举时与无权同形，见 I03）：`NOT_FOUND`（404）。

### 5.1 创建空知识包

`POST /v1/knowledge/packs`（需登录）

请求头：`X-Request-Id` 可选。请求体可为空对象 `{}`。本约不要求标题或封面；服务端可在内部保留占位名，但不作为本切片请求字段。

成功 `201`：

| 字段 | 说明 |
|---|---|
| `pack_id` | 新知识包标识 |
| `account` | 见 A1 §4.6；此时 `has_first_pack` 不因本次创建而变 |
| `next_step` | 见 A1 §3.4 |

同一学习者可以有多个知识包。本切片导航只关心「是否已有首个已成地图的包」，不在本接口做「只能创建一个」的限制。

### 5.2 申请材料预签名上传

`POST /v1/knowledge/materials/upload-url`（需登录）

请求头：`X-Request-Id` 可选。

请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `pack_id` | 是 | 目标知识包；不存在或不属于当前学习者则为 `NOT_FOUND` |
| `source` | 是 | `camera` / `file` / `paste_note` |
| `content_type` | 是 | 见 4.2；须与随后 PUT 使用的 `Content-Type` 一致 |
| `byte_size` | 是 | 将上传的字节数，正整数 |
| `filename` | 否 | 仅作展示用元数据，不得当作对象键，不得含路径 |

成功 `200`：

| 字段 | 说明 |
|---|---|
| `material_id` | 材料标识，随后提交导入使用 |
| `pack_id` | 回显 |
| `source` | 回显 |
| `upload_url` | S3 兼容预签名 URL |
| `upload_method` | 固定为 `PUT` |
| `upload_headers` | 客户端 PUT 时必须带上的头（至少包含与申请一致的 `Content-Type`） |
| `expires_in` | 预签名剩余有效秒数（具体秒数由实现决定，本约不锁死） |
| `account` | 见 A1 §4.6 |
| `next_step` | 见 A1 §3.4 |

客户端按 `upload_method` 与 `upload_headers` 把字节 PUT 到 `upload_url`，不经过本 API。预签名过期后应重新申请（得到新的 `material_id` 即可）；被放弃的待上传材料不阻断同一知识包再次申请。对象键由服务端生成并只留在服务端元数据 / 作业上，成功响应不回传对象键。

### 5.3 提交导入

`POST /v1/knowledge/imports`（需登录）

请求头：`Idempotency-Key` 必填，缺则 `VALIDATION_MISSING_FIELD`；`X-Request-Id` 可选。

请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `pack_id` | 是 | 须与材料所属知识包一致 |
| `material_id` | 是 | 须已申请、且对象存储中已有完整字节 |

材料尚未上传完成、字节与申报 `byte_size` 不符、或预签名已过期且对象不存在：`VALIDATION_MATERIAL_NOT_UPLOADED`（422），不创建作业。`pack_id` / `material_id` 不存在或不属于当前学习者、或二者不匹配：`NOT_FOUND`。同一知识包已有 `accepted` 或 `running` 的导入作业：`CONFLICT`（409），不创建第二条进行中的作业。

成功 `202`，响应体为作业资源（见 5.4）。此时 `status` 为 `accepted`（幂等重放见下），`map_ready` 为 `false`，并入队等待 A5 处理。本接口是同步受理，**不得**在请求内跑完 S01。

幂等：

- 同一学习者、同一 `Idempotency-Key`、同一请求体：不创建新作业，HTTP 仍为 `202`，`job_id` 与首次相同。响应体中的作业字段与**当时** `GET /v1/knowledge/jobs/{id}` 一致，以便杀进程后重放能看到已经 `map_ready` 的结果，而不是一份过期的 `accepted` 快照。
- 同一密钥配了不同请求体：`IDEMPOTENCY_KEY_MISMATCH`（409），不执行。

失败可重试的作业：客户端使用**新的** `Idempotency-Key`，带上同一 `pack_id` 与同一 `material_id` 再次调用本接口，创建一条新作业。服务端必须复用已传材料的对象键，不得要求用户把同一文件再传一遍，除非材料损坏或校验失败需要换文件（I05）。本刀不另设「重试」子资源。

免费导入间隔（完整版 PRD 曾默认 20 分钟）是否生效、时长是多少，本约不锁死。若后续确认仍生效，须在**本接口受理时**由服务端判定，命中则 `RATE_LIMITED`（429），可在 `details.retry_after_seconds` 给出剩余秒数；与等待页的地图生成进度分开展示，不得混成同一种转圈，也不得擅自加 Plus 解除条（见第 8 节）。

### 5.4 查询作业

`GET /v1/knowledge/jobs/{id}`（需登录）

请求头：`X-Request-Id` 可选。路径参数 `id` 即 `job_id`。

成功 `200`：

| 字段 | 说明 |
|---|---|
| `job_id` | 作业标识 |
| `pack_id` | 所属知识包 |
| `material_id` | 已传材料 |
| `source` | 该材料的入口类型 |
| `status` | 见 4.3 |
| `map_ready` | 地图是否可进；仅 `status=map_ready` 时为 `true` |
| `retryable` | 是否可用同一材料再次提交导入 |
| `progress_message` | 可选，给人看的进度说明，可随端本地化；客户端不把它当状态机 |
| `failure_code` | 失败时可选的稳定机器码；未失败为省略或 `null`。具体失败码由 A5 补丁追加，本约不预先锁定挖掘 / 出题失败清单 |
| `failure_message` | 失败时可选的可读原因；未失败为省略或 `null`。不得包含材料正文 |
| `account` | 见 A1 §4.6 |
| `next_step` | 见 A1 §3.4 |

作业不属于当前学习者或不存在：`NOT_FOUND`。查询是只读的，不改变作业状态，也不触发 S01 / S02。

等待页行为属于端上导航，但须遵守 phase B 已锁规则：未 `map_ready` 不得进默认首页入口；返回只回来源页；不做「完成后通知我」。本契约不规定轮询间隔。跳过首包不进入等待页，不适用本条的作业闸门。

### 5.5 跳过首包（「我没有材料」）

`POST /v1/knowledge/first-pack/skip`（需登录）

路径写死如上。`first-pack` 是名词资源（首包步骤），`skip` 是该资源下的明确子资源，写法与 A1 的 `POST /v1/identity/session/revoke` 同类，符合 I03。

请求头：`Idempotency-Key` 必填，缺则 `VALIDATION_MISSING_FIELD`；`X-Request-Id` 可选。请求体可为空对象 `{}`，或不传请求体。本接口不接受材料、知识包或作业标识，也不创建导入作业。

成功 `200`：

| 字段 | 说明 |
|---|---|
| `account` | 见 A1 §4.6；成功后 `has_first_pack` 为 `true` |
| `next_step` | 建档已完成则为 `READY_HOME`，会话刷新不得打回 P04；建档未完成则为 `NEED_ONBOARDING` |

幂等：

- 同一学习者、同一 `Idempotency-Key`、同一请求体：不重复执行，HTTP 仍为 `200`，响应体与当时的账号概况和 `next_step` 一致。
- 同一密钥配了不同请求体：`IDEMPOTENCY_KEY_MISMATCH`（409），不执行。
- 若该学习者已经 `has_first_pack=true`（例如已经 `map_ready`，或此前已经跳过）再调用本接口：仍返回 `200`，`has_first_pack` 保持 `true`，不把已完成打回未完成，不清除已有知识包或作业，也不新建导入作业。换用新的 `Idempotency-Key` 亦同。

## 6. 与 A5 的界限

- 本刀实现范围止于：知识包创建、预签名发放、导入受理（入队 + `202`）、作业查询信封、跳过首包，以及 `has_first_pack` 写入规则。
- A5 负责把 `accepted` 迁到 `running` / `map_ready` / 失败态，调用 airuntime 做 S01，并在地图已成之后再触发 S02 小批量预出题。预出题成功与否不得改变 `map_ready`，也不得成为等待页闸门的一部分。
- 本约不为 S01 / S02 定义 prompt、请求体、场景内部参数或 worker 回调接口。用量记账（S01 流水、默认不落教材原文）由 D03 / I04 约束，不在本接口展开。
- 作业查询预留的状态已够 A5 接入；A5 若需追加失败码或可选进度字段，用兼容补丁，不得悄悄改 `status` 枚举已有值的含义。

## 7. 错误码

沿用 I03 族与 A1 已有鉴权 / 幂等 / 限流码，只在相应族下新增本切片用到的码，不另起拼写。身份域专用码（如 `AUTH_OTP_*`、`VALIDATION_INVALID_PHONE`）仍只用于身份接口，知识域不要拿来表示别的含义。

| `code` | HTTP | 何时 |
|---|---|---|
| `AUTH_REQUIRED` | 401 | 需登录的接口没有访问令牌 |
| `AUTH_EXPIRED` | 401 | 访问令牌过期或已吊销 |
| `AUTH_FORBIDDEN` | 403 | 已登录但无权（本切片知识写自己的包一般不出现；不可枚举的跨用户访问用 `NOT_FOUND`） |
| `AUTH_WRONG_REALM` | 403 | 用内部令牌打学习者前缀，或相反 |
| `VALIDATION_MISSING_FIELD` | 400 | 缺必填字段，或缺 `Idempotency-Key` |
| `VALIDATION_INVALID_SOURCE` | 400 | `source` 不是 `camera` / `file` / `paste_note` |
| `VALIDATION_UNSUPPORTED_MEDIA` | 400 | `content_type` 不在允许表，或与 `source` 不匹配 |
| `VALIDATION_MEDIA_TOO_LARGE` | 400 | 申报或实际上传字节超过服务端上限（上限本约不锁死） |
| `VALIDATION_MATERIAL_NOT_UPLOADED` | 422 | 提交导入时对象尚未完整可读 |
| `NOT_FOUND` | 404 | 知识包、材料或作业不存在，或不属于当前学习者 |
| `CONFLICT` | 409 | 同一知识包已有进行中的导入作业等、当前状态不允许该操作 |
| `IDEMPOTENCY_KEY_MISMATCH` | 409 | 同一幂等键配了不同请求体 |
| `RATE_LIMITED` | 429 | 导入受理被限流，或（若日后确认）命中导入间隔 |
| `INTERNAL` | 500 | 未分类的服务端失败；不得用它吞掉校验、冲突、限流或作业失败 |

机器源中的 `ErrorBody.code` 枚举在 A1 清单上**只追加**本表新增项（`VALIDATION_INVALID_SOURCE`、`VALIDATION_UNSUPPORTED_MEDIA`、`VALIDATION_MEDIA_TOO_LARGE`、`VALIDATION_MATERIAL_NOT_UPLOADED`、`NOT_FOUND`、`CONFLICT`）。A1 已有码的拼写与含义不变。
