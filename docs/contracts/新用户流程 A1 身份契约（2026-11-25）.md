## 1. 范围

本契约只覆盖学习者身份域：

- 短信验证码发送与校验
- 会话签发、刷新与吊销
- 建档 7 步读写与中途续答
- 校验成功后的「下一步」枚举
- 界面语言与默认区号偏好

不在本契约：

- 知识包、预签名、导入作业（附录 A4 / A5）
- 系统权限调起与可选偏好上报（端上完成，不作为账号鉴权，也不阻断主链路）
- 微信 / 支付宝登录（页上可展示，本阶段不提供接口，不得假登录）
- 默认首页内容、等待页动画、端 UI 样式
- 后管 / 内部身份域（`/internal/v1/**`）

三端共用这一套路径、字段与错误码，不允许各端私改。安卓启动页与欢迎页不因本契约重做；iOS / 鸿蒙补齐这两页时，登录态与「下一步」仍以本契约为准。

## 2. 平台约定（沿用 I03，不另起一套）

- 学习者路径：`/v1/identity/...`。名词资源，动作用 HTTP 方法或明确子资源。
- 访问令牌：`Authorization: Bearer`；只允许访问 `/v1/**`。内部令牌打到本前缀一律 `AUTH_WRONG_REALM`。
- 每个响应带 `X-Request-Id`；请求可带同名头，服务端也可补发。
- 成功：直接返回资源 JSON，用 HTTP 状态表达结果。失败统一信封：

```json
{
  "error": {
    "code": "AUTH_EXPIRED",
    "message": "给人看的说明，可随端做本地化",
    "details": {}
  },
  "request_id": "…"
}
```

客户端只依赖 `code`，不解析 `message`。`details` 可选，不得放入验证码明文、完整手机号以外的敏感原文、教材、提示词或密钥。

- 发码请求必须带 `Idempotency-Key`。同一身份、同一密钥、同一请求体返回与首次相同的结果，不得重复发短信；同一密钥不同请求体返回 `IDEMPOTENCY_KEY_MISMATCH`，不执行。
- 短信与模型提供方可 mock；本契约不锁定供应商，也不把供应商写进路径。密钥不进仓库、不进 Cloud 任务正文。

## 3. 标识与枚举

### 3.1 区号与语言

| 字段 | 允许值 | 说明 |
|---|---|---|
| `region_code` | `+86`、`+852` | 仅中国大陆与香港；其它值 `VALIDATION_UNSUPPORTED_REGION` |
| `phone_national` | 数字字符串，不含区号、空格与短横 | 非法格式 `VALIDATION_INVALID_PHONE` |
| `locale` | `zh-Hans`、`zh-Hant` | 简体 / 繁体；影响文案资源，**不是**第二套账号。其它值 `VALIDATION_UNSUPPORTED_LOCALE` |

登录 / 注册页在未建会话前即可选择语言与区号：把 `locale`、`region_code` 放在发码与验码请求里；验码成功后写入该账号偏好。建会话后用 profile 读写，不必再走 onboarding。

### 3.2 发码目的

`purpose`：`register` | `login`。其它值 `VALIDATION_INVALID_PURPOSE`。

登录号未注册对应现行稿「无此账号」：在 **发码** 阶段返回 `AUTH_ACCOUNT_NOT_FOUND`，不进入验证码页。该页「创建账号」走注册发码；「用其他方式登录」不得调用本契约接口冒充成功。

注册号已存在：发码返回 `AUTH_ACCOUNT_EXISTS`。不自动登录，客户端走已有的「已有账号」入口，本契约不另造页面。

### 3.3 建档步骤 `step_id`

进度条共 7 步，昵称是第 1 步，原六题为第 2–7 步。权限页不另加步数，也不写入本资源。

| 顺序 | `step_id` | 对应页 |
|---|---|---|
| 1 | `nickname` | 补充昵称 |
| 2 | `age` | P03-1 年龄（含「18 岁以下」标记，本切片只写入，不在本契约展开支付 / 社交策略） |
| 3 | `study_or_work` | P03-2 学生或在职 |
| 4 | `identity` | P03-3 身份 |
| 5 | `how_to_address` | P03-4 怎么称呼你（与第 1 步昵称不是同一步，不得合并） |
| 6 | `exam_track` | P03-5 备考方向 |
| 7 | `daily_time` | P03-6 每天投入 |

第 2–7 步为单选。本版锁定 `step_id` 与提交形态；**各题选项的稳定 key 与文案不在本版锁死**，等与现行帧文案对齐后以补丁追加，不阻塞发码、会话与下一步枚举的实现。选项 key 未对齐前，服务端对 `answer` 做非空字符串校验即可，不得由三端各编一套选项码。

不得跳步写入。只允许提交「当前待填步」或回写已完成步。中途退出后再进，从第一道未完成步续答。

### 3.4 下一步 `next_step`

由服务端给出，三端必须按此路由，不得自行根据本地标志猜测。

| 值 | 含义 | 客户端去向 |
|---|---|---|
| `NEED_ONBOARDING` | 建档未完成 | P03 当前待填步（新用户或未走完 7 步） |
| `NEED_FIRST_PACK` | 建档已完成，尚无首个知识包 | 权限页（若尚未展示）或 P04 |
| `READY_HOME` | 可进默认首页入口 | 只提供路由出口，本切片不实现首页内容 |

实施假设（方案 §9 **H3**，不是已确认产品口径）：老用户验证码通过后，若建档与首包均已完成，则 `READY_HOME`；仅未完成建档者进 7 步；建档完成但无首包者 `NEED_FIRST_PACK`。H3 若被否定，只改服务端判定，不改枚举名。

`otp/verify`、`session/refresh`、`GET /v1/identity/onboarding`、`PUT /v1/identity/onboarding` 的成功响应都带当前 `next_step`（以及账号概况），避免三端状态分叉。

「我没有材料」直接进首页、等待页完成后再进首页，属于知识域 / 导航，不在本契约用一个新枚举表达。

## 4. 接口

未特别声明的接口均产生 JSON。下列「需登录」的接口无令牌为 `AUTH_REQUIRED`（401），令牌过期或已吊销为 `AUTH_EXPIRED`（401）。

### 4.1 请求短信验证码

`POST /v1/identity/otp/send`（不需登录）

请求头：`Idempotency-Key` 必填；`X-Request-Id` 可选。

请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `region_code` | 是 | 见 3.1 |
| `phone_national` | 是 | 见 3.1 |
| `purpose` | 是 | `register` 或 `login` |
| `locale` | 否 | 未建会话时的界面语言；缺省不改已有偏好，新账号缺省 `zh-Hans` |

成功 `200`：

| 字段 | 说明 |
|---|---|
| `retry_after_seconds` | 距允许下次发码的秒数 |
| `destination_hint` | 可展示的掩码号码，不得回发明文验证码 |

服务端按号码 / 设备限流，触发 `RATE_LIMITED`（429），可在 `details.retry_after_seconds` 给出等待秒数。限流阈值本约不锁死。验证码不是长期凭证，不得作为后续业务请求的令牌。

### 4.2 校验验证码并建会话

`POST /v1/identity/otp/verify`（不需登录）

请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `region_code` | 是 | 须与发码一致 |
| `phone_national` | 是 | 须与发码一致 |
| `purpose` | 是 | 须与发码一致 |
| `code` | 是 | 6 位数字；格式错 `VALIDATION_INVALID_OTP_FORMAT` |
| `locale` | 否 | 成功时写入账号偏好 |

成功 `200`：

| 字段 | 说明 |
|---|---|
| `access_token` | 短时访问令牌 |
| `refresh_token` | 可吊销刷新令牌 |
| `expires_in` | 访问令牌存活秒数（具体秒数由实现决定，本约不锁死） |
| `account` | 见 4.6 |
| `next_step` | 见 3.4 |
| `profile` | 当前 `locale` 与 `region_code` |

错误：`AUTH_OTP_INVALID`（码错）、`AUTH_OTP_EXPIRED`（已过期须重发）、`AUTH_OTP_MAX_ATTEMPTS`（次数用尽须重发）、以及发码阶段同类的账号存在性错误（防竞态）。不得在错误信封里回显用户输入的验证码。

### 4.3 刷新会话

`POST /v1/identity/session/refresh`（不使用已过期的访问令牌）

请求体：`refresh_token` 必填。

成功 `200`：新的 `access_token`、`refresh_token`（允许旋转）、`expires_in`、`account`、`next_step`、`profile`。刷新令牌无效或已吊销：`AUTH_EXPIRED`。

### 4.4 吊销会话

`POST /v1/identity/session/revoke`（需登录，或在体中提交要吊销的 `refresh_token`）

成功 `204`，无响应体。已失效的令牌再吊销仍返回 `204`，以便客户端登出幂等。吊销后旧访问令牌与对应刷新令牌均不可用。

### 4.5 读 / 写建档

`GET /v1/identity/onboarding`（需登录）

成功 `200`：

| 字段 | 说明 |
|---|---|
| `current_step_id` | 当前待填 `step_id`；已全部完成则为 `null` |
| `current_index` | 1–7；已完成则为 `7` |
| `completed` | 7 步是否都已写入 |
| `nickname` | 第 1 步已提交的昵称，未提交为 `null` |
| `steps` | 长度为 7 的数组，元素含 `step_id`、`index`、`status`（`pending` 或 `completed`）与 `answer`。`nickname` 步的 `answer` 与 `nickname` 相同。未完成步 `answer` 为 `null` |
| `account` | 见 4.6 |
| `next_step` | 见 3.4 |

`PUT /v1/identity/onboarding`（需登录）

请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `step_id` | 是 | 本次提交的步骤 |
| `nickname` | 当 `step_id=nickname` | 非空字符串；超限或非法 `VALIDATION_NICKNAME`。本约不锁死字数上限 |
| `answer` | 当 `step_id` 为第 2–7 步 | 非空字符串；空值 `VALIDATION_INVALID_STEP_ANSWER` |

成功 `200`，响应与 GET 相同（已反映本次写入）。提交非当前待填、且不是回写已完成步：`VALIDATION_STEP_OUT_OF_ORDER`（422）。未知 `step_id`：`VALIDATION_INVALID_STEP`。

建档写完第 7 步后，`completed=true`，`next_step` 按 3.4 计算（通常为 `NEED_FIRST_PACK`，若已有首包则为 `READY_HOME`）。末步按钮文案「建档完成，上传第一份材料」属 UI，不进本契约。

### 4.6 账号概况 `account`

| 字段 | 说明 |
|---|---|
| `user_id` | 稳定学习者标识 |
| `is_new_user` | 本次验码是否刚创建账号 |
| `onboarding_completed` | 是否已完成 7 步 |
| `has_first_pack` | 是否已有首个知识包（由知识域写入，身份域只读此标志以计算 `next_step`） |

`is_new_user` 仅描述本次验码，路由以 `next_step` 为准。

### 4.7 语言与区号偏好

`GET /v1/identity/profile`（需登录）

成功 `200`：`locale`、`region_code`。

`PUT /v1/identity/profile`（需登录）

请求体可只带要改的字段：`locale` 和 / 或 `region_code`。成功 `200` 返回完整 profile。非法值见 3.1。改区号只改默认偏好，不改已绑定的登录号码。

## 5. 错误码

只在 I03 已有族下新增，不另起拼写。本切片身份域用到的码：

| `code` | HTTP | 何时 |
|---|---|---|
| `AUTH_REQUIRED` | 401 | 需登录的接口没有访问令牌 |
| `AUTH_EXPIRED` | 401 | 访问令牌或刷新令牌过期、已吊销 |
| `AUTH_FORBIDDEN` | 403 | 已登录但无权（本切片身份写自己的建档一般不出现） |
| `AUTH_WRONG_REALM` | 403 | 用内部令牌打学习者前缀，或相反 |
| `AUTH_ACCOUNT_NOT_FOUND` | 404 | `purpose=login` 且号码未注册（「无此账号」） |
| `AUTH_ACCOUNT_EXISTS` | 409 | `purpose=register` 且号码已注册 |
| `AUTH_OTP_INVALID` | 401 | 验证码不正确 |
| `AUTH_OTP_EXPIRED` | 401 | 验证码已过期 |
| `AUTH_OTP_MAX_ATTEMPTS` | 403 | 该次验证码尝试次数用尽，须重发 |
| `VALIDATION_INVALID_PHONE` | 400 | 号码格式不合法 |
| `VALIDATION_UNSUPPORTED_REGION` | 400 | 区号不是 `+86` / `+852` |
| `VALIDATION_UNSUPPORTED_LOCALE` | 400 | 语言不是简 / 繁对应值 |
| `VALIDATION_INVALID_PURPOSE` | 400 | `purpose` 非法 |
| `VALIDATION_INVALID_OTP_FORMAT` | 400 | 验证码不是 6 位数字 |
| `VALIDATION_MISSING_FIELD` | 400 | 缺必填字段或缺 `Idempotency-Key` |
| `VALIDATION_NICKNAME` | 422 | 昵称不合法 |
| `VALIDATION_INVALID_STEP` | 400 | 未知 `step_id` |
| `VALIDATION_INVALID_STEP_ANSWER` | 422 | 单选答案为空或非法 |
| `VALIDATION_STEP_OUT_OF_ORDER` | 422 | 跳步提交 |
| `IDEMPOTENCY_KEY_MISMATCH` | 409 | 同一幂等键配了不同请求体 |
| `RATE_LIMITED` | 429 | 发码或验码被限流 |
| `INTERNAL` | 500 | 未分类的服务端失败；不得用它吞掉验码或限流失败 |
