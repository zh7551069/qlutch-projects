## 2. 本轮锁住

- A4 已锁的 `status` 枚举与不变量保持不变：`map_ready == (status == map_ready)`，`retryable == (status == failed_retryable)`。等待页只有 `map_ready` 才能进默认首页入口。
- A4 写 `accepted`；A5 把作业迁到 `running` / `map_ready` / `failed_retryable` / `failed_terminal`。`map_ready` 必须先有可进入的地图再可见；本切片不得从 `map_ready` 再迁走。
- 生产路径必须经 `services/airuntime` 真正跑 S01；禁止 mock 直接 `map_ready`。测试夹具（如 `TestingSetJobStatus`）不得是 HTTP 路由，不得走进生产路径。
- 同一材料、同一模板版本的成功地图允许经 airuntime 判定后复用并记账，这不是夹具捷径。
- `map_ready` 已提交之后才触发 S02 小批量预出题；S02 成败不影响 `map_ready` / `has_first_pack`，也不进入等待页闸门。不为 S02 另设查询字段或状态值。
- 首次 `map_ready` 后 `has_first_pack=true`，与 A4 跳过规则一致；不新增 `next_step` 值，不改 A1 身份 schema。空包与 `202` 受理仍不得置真。
- `GET` 作业查询不变状态、不触发 S01 / S02。查询字段与 A4 兼容。
- 用户侧对失败可重试作业：新的 `Idempotency-Key` + 同一 `pack_id` / `material_id` 再提交导入，复用对象键，不另设「重试」子资源。材料对象不可恢复地缺失或损坏迁 `failed_terminal`；材料仍完整可读且无已补丁终态原因时，优先 `failed_retryable`。
- S01 账本对齐 D03 / D04 / I04：分场景与子类、识别转写分账、能缓存则记账可见、只送必要片段、禁止完整教材进模板、按档位不按供应商、失败默认不误扣、S02 / S05 不与 S01 混账。默认不存教材原文与完整提示词。不指定供应商、温度或费率。
- 本轮不改机器源，仍以 A4 yaml / 仓内 `openapi.yaml`（`0.1.1-C`，md5 `c2b40034c9ee508d8f5c4281c4fb309a`）为准。不为抖音 / B 站 / ISBN / 书名开 endpoint，不加后管路径，不定 prompt 与 worker 内部协议。配置名对齐 `QLUTCH_S3_*`、`QLUTCH_WORKER_QUEUE`、`QLUTCH_WORKER_HEARTBEAT`，不写密钥与厂商取值。
- H3 仍是实施假设。A4-O2 数字与导入间隔（方案 §7.6 / I05）仍开放，不得写成已锁产品口径。
- 本约不部署，也不把中间过程的单独产品验收写成实施闸门。
